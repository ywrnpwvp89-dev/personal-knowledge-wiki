# Onboarding and architecture proposal

Ask no more than eight focused questions in the first interaction. Do not request passwords, private keys, or unnecessary personally identifying information. Summarize answers back as assumptions and ask the user to correct them.

Architecture proposal should include:

1. top-level areas and their purpose;
2. note types and required frontmatter;
3. source-to-topic linking and naming conventions;
4. dashboards for deadlines, tasks, review, and decisions;
5. privacy boundaries and excluded paths;
6. migration/maintenance rules for later uploads.

After explicit confirmation, create an architecture note with a Mermaid flowchart. Keep the diagram conceptual and readable; it should show intake, source cards, topic notes, dashboards, and the index, plus any user-specific areas. Do not claim that a diagram proves the files were created.
